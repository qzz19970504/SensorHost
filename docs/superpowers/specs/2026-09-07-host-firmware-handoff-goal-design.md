# 上位机固件接口交接文档 Goal 设计

## 目标

生成一份可直接交给 Codex 以 Goal 形式执行的中文 Markdown 提示词。该 Goal 通过静态分析 STM32、ESP32 和现有上位机三个独立仓库，产出一份简短但足够完成交接的中文单文档。

## 输入范围

- `D:\Codes\STM32\STM32407ZG_JY61PL_II3DWB_UART_V2`：STM32 震动采集固件，作为设备行为和协议的主要事实源。
- `D:\Codes\ESP32\ESP32_WIFI_UART_BRIDGE`：ESP32 UART/TCP 透明传输固件，作为 Wi-Fi 接入方式的事实源。
- `D:\Codes\SensorHost`：现有半成品上位机，仅作为协议解析、连接和调用流程的参考实现。

事实优先级为：实现代码与测试、黄金帧与验收脚本、当前文档、现有上位机行为。冲突无法消解时必须标记“待确认”，不得猜测。

## 输出

- Goal 提示词：`D:\Codes\SensorHost\上位机固件接口交接文档生成任务.md`
- Goal 产物：`D:\Codes\SensorHost\docs\上位机固件接口交接手册.md`

最终手册为单一、中文命名的 Markdown 文件，面向接手开发新上位机的工程师。

## 手册范围

只保留完成固件接入所需内容：

1. 系统链路与三个项目的职责边界。
2. STM32、ESP32 的连接方式、默认参数和启动前提。
3. USB CDC 与 ESP32 Wi-Fi/TCP 两种上位机接入流程。
4. SDF1 帧格式、消息类型、CRC、数据换算与流解析要求。
5. AT 命令、命令前置条件、状态转换、幂等性、超时和重试规则。
6. STATUS、文本诊断、错误处理和恢复建议。
7. 实时流与 SD 存档/导出的差异、带宽语义和已知限制。
8. 新上位机的最小实现与联调检查清单。

不评价现有上位机 UI，不提出界面改造方案，不叙述冗长开发历史，不复制与上位机接入无关的固件内部实现。

## 执行约束

- 只做静态分析，不连接、烧录、配置或控制硬件。
- 不修改三个仓库的实现代码。
- 每个关键数值、命令或行为必须能追溯到仓库中的代码、测试或文档。
- 对需要硬件才能确认的事实标注“待实机确认”。
- 文档使用简洁中文；表格仅用于协议字段、命令和关键差异。
- 完成前检查术语、数值、命令、路径、内部链接和事实来源的一致性。

## 验收标准

- 上位机开发人员无需阅读全部固件代码，即可知道如何连接、解析、控制和诊断设备。
- CDC 与 Wi-Fi/TCP 的差异明确，ESP32 的透明传输边界明确。
- 不把半成品上位机行为错误地提升为协议规范。
- 没有无来源推断、未解释缩写、重复大段内容或遗留占位符。
